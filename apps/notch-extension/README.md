# AITimeline 刘海探路扩展(SuperIsland)

把本机知识库里「该回来找你」的知识卡藏在 MacBook 刘海里,鼠标甩上去才展开。

**这是探路件,不是产品。** 它存在的唯一目的,是验证「把知识卡藏在刘海里、
用户主动去拉才看」这个交互到底值不值得做。验完就该退役——正式版要么做进
自家的 Electron 桌面壳(画布自由、不依赖第三方),要么就不做。

## 为什么是探路件

- **依赖第三方**:宿主是 [SuperIsland](https://github.com/shobhit99/SuperIsland),
  一个 macOS 刘海应用。它的仓库**没有 LICENSE 文件**,法律上默认「保留所有权利」。
  自己装着用没问题,但不能让 AITimeline 的用户「先去装它」。
- **画不了图**:它的画布不是网页,是一套固定组件。`image` 只接受图片网址,
  不能画 SVG、不能自己画线。概念图搬不过去——要么服务端先渲染成 PNG,
  要么这条路只能显示文字。
- **代码是抄的**:它的 JS 环境不支持引用别的文件,一个扩展只能有一个 `index.js`。
  时间文案和复习到期判断是从 `apps/extension/lib/injectCore.js` 逐字搬过来的,
  **改一处要改两处**。

## 装法

1. 装上并启动 SuperIsland(从 [官网](https://dynamicisland.app/) 或
   [仓库 Releases](https://github.com/shobhit99/SuperIsland/releases))。
   它跑起来才会建配置目录。
2. 起本机 API:仓库根目录 `npm run dev:api`(监听 127.0.0.1:8787)。
   知识库里得有卡:`curl -s http://127.0.0.1:8787/api/inject/cards` 应返回 1-3 张。
3. 把本目录拷进扩展目录:

   ```bash
   mkdir -p ~/Library/Application\ Support/SuperIsland/Extensions
   cp -R apps/notch-extension ~/Library/Application\ Support/SuperIsland/Extensions/aitimeline
   ```

4. 重启 SuperIsland,在它的设置里确认扩展已加载。

## 该看到什么

- **静默态**:刘海左边一个小书本图标,右边一个数字(有该复习的卡时是蓝色,
  否则灰色)。**一张卡都没有的时候整个模块让位**,音乐控件之类的东西回来占着,
  不会留一条空白黑条。
- **鼠标甩上去展开**:卡片标题(最多两行)+「三天前存的 · 该复习了」+ 第几张/共几张。
- **再展开是详情**:摘要(可滚)、出处、概念,加「下一张」和「在知识库中打开」两个按钮。
- **API 挂掉时**:图标变成警告三角,展开后的那行小字会追加「本机 AITimeline 没有运行」,
  同时**保留上一批卡**——知识卡不会 60 秒就过期,拿旧的看比空着强。

## 三条有意为之的设计约束

改代码前先读这三条,它们都是踩过坑或核实过源码才定下来的。

**一、永不主动弹。** 代码里一次都没调用 `SuperIsland.island.activate()`。
注意 manifest 的 `activationTriggers` **不管弹不弹**——它只管宿主要不要给扩展
注册重画定时器(`ExtensionManager.swift:436-442`)。必须写 `"timer"`,否则宿主
只在激活那一瞬间读一次视图,而那时候网络还没回来,刘海会永远停在「没有卡」的
空状态再也不更新。定时器回调只重画、不弹岛(`ExtensionManager.swift:462-464`)。

**二、不发曝光信号。** 知识卡有条规则是「曝光 5 次且零互动就从时间线下架」
(`packages/core/src/ranking/lifecycle.ts:52`),而纯曝光信号不做当日合并。
刘海面要是照 X 注入面那样发曝光,几分钟就能把一张卡从网页信息流和 X 注入面
**一起**弄消失。所以这里只在用户真的点开时发一条 open 信号。

代价:这个面的行为数据是瞎的。正式版应该给信号加「来自哪个面」的字段,
那是核心包的改动(要动类型定义、去重哈希、当日合并、生命周期统计四处),
不在探路范围内。

另外要知道:点开发的那条信号会给卡挂上第二条下架时钟——「读过之后 30 天
没再互动就下架」(`lifecycle.ts:56-63`)。这跟现有 X 注入面点击时的行为
完全一致(信号形状是从 `injectCore.js` 的 open 分支抄的),不是新增风险。

**三、有刘海的 Mac 上 `compact()` 是死代码。** 宿主默认走
`minimalCompact` 的 leading/trailing 两格(`CompactView.swift:9-20` 三条分支),
`compact()` 只在没刘海的机器、或用户关掉侧边槽位时才用。所以错误提示不能只写在
`compact()` 里——那样有刘海的人永远看不到。

还有:从 `minimalCompact` 返回 `null` **不等于隐身**。宿主把 null 当空节点画,
但刘海照样按 manifest 声明撑宽(左右各 56 点),结果是一条什么都没有的黑条。
真正让位的开关是 `precedence` 返回 0(`AppState.swift:930-934`)。

## 已知没做的

- 概念图和配图(画布画不了,见上)。
- 「记住了 / 不想看」这类互动(探路阶段只验交互值不值得,不做信号闭环)。
- 多显示器、合盖、全屏应用下的行为——这些是刘海这个位置的结构性问题,
  不是扩展能解决的,留给正式版决策时算覆盖率。

## 验完要回答的问题

1. 甩鼠标到刘海看知识卡,一天下来你主动去拉了几次?
2. 拉开之后,你是真的读进去了,还是扫一眼就关?
3. 静默态那个数字,你会去看吗?还是完全无视?
4. 跟 X 时间线里的注入卡比,哪个更容易让你真的读一张卡?

这四个问题的答案决定要不要花两周做正式版。
