# AITimeline Clipper(Chrome 插件)

两条通路:

- **剪藏**:在 x.com / twitter.com 的每条推文操作栏里加一个「保存」按钮,点击后把推文
  (正文、作者、永久链接、发布时间)送进本机 AITimeline API,登记成待转化的来源。
  悬停按钮可选分类;保存转成知识卡后按钮推进「已成卡」并弹出页内回执。
- **注入**:从本机 API 拉「该回来找用户」的知识卡(复习到期优先),以 X 原生帖的
  外观插进主时间线;拉不到卡就完全不注入。文件:`inject.js` + `lib/injectCore.js`
  (纯逻辑,有 Vitest 单测)+ `inject.css`。

通路:content script 抓取推文 → `chrome.runtime.sendMessage` → background
service worker → `POST http://127.0.0.1:8787/api/captures/source`。
走 service worker 是为了绕开页面源的 CORS 限制;推文正文随请求一起提交
(`capturedText`),因为服务器抓 x.com 只能拿到登录墙,剪藏就是正文的唯一来源。

纯 JS,无构建步骤,无第三方依赖。

## 人工验收步骤(剪藏)

1. 起本机 API:仓库根目录执行 `npm run dev:api`(监听 127.0.0.1:8787)。
2. 打开 Chrome,进入 `chrome://extensions`,右上角打开「开发者模式」。
3. 点「加载已解压的扩展程序」,选择本目录(`apps/extension`)。
4. 打开 https://x.com 并登录,滚动信息流,确认每条推文的操作栏
   (回复/转发/喜欢那一排)末尾出现灰色「保存」按钮;继续滚动,新加载的
   推文也要有按钮。
5. **挂载可靠性**:在时间线上点赞/取消点赞某条推文(触发 React 重渲染),
   按钮不消失;若消失,一两秒内被自动补挂回来。
6. 点某条推文的「保存」:按钮先变「保存中…」,成功后变绿色「已保存」。
7. **保存分类**:悬停另一条推文的「保存」约半秒,按钮下方浮出「存进分类」
   菜单(候选来自知识库的兴趣主题和学习目标,还有自由输入框);点某个分类
   即保存。验证分类进了候选:

   ```bash
   curl -s http://127.0.0.1:8787/api/source-candidates | python3 -c "import json,sys; [print(r['candidate']['source']['url'], r['candidate']['conceptIds']) for r in json.load(sys.stdin)['records'] if r.get('intakeKind')=='browser_share']"
   ```

   该条 candidate 的 `conceptIds` 应含所选分类。直接点「保存」(不悬停不选
   分类)行为与第 6 步完全一致。
8. **折叠长文存全文**:找一条时间线上被折叠的长推文(正文末尾有「显示更多」),
   直接点「保存」:按钮先变「保存中…」,页面上那条推文当场展开(不跳转),
   然后才发保存请求。核对存进去的是全文而不是半截:

   ```bash
   curl -s http://127.0.0.1:8787/api/source-candidates | python3 -c "import json,sys; [print(len(r['candidate'].get('capturedText','')), r['candidate']['source']['url']) for r in json.load(sys.stdin)['records'] if r.get('intakeKind')=='browser_share']"
   ```

   字数应与展开后的正文相当。反例:一条正文完整、只是**引用**了被折叠长推的
   推文,按钮点下去不该触发展开动作(引用块里的折叠标记不算数)。
   X Article(长文章)要在文章页里保存,`capturedText` 是完整正文。
9. **广告位不挂按钮**:滚到一条推广/广告推文(带「广告」标记),它的操作栏里
   不应出现「保存」按钮(广告没有永久链接,存不了)。
10. **成卡回执**:保存后等后台策展跑完(保存会自动催一轮,通常几秒到几十秒),
    按钮自动推进「已成卡」,页面底部滑入蓝色回执「已转成知识卡 · 在知识库中
    打开」;点回执新开标签页进知识库(127.0.0.1:5173)。
11. 对同一条推文再点一次「保存」,按钮应变「已存过」,候选池里不新增记录;
    如果它已经转成卡,按钮直接显示「已成卡」。
12. **断连演练**:停掉 API 再点「保存」,按钮变红色「重试」,悬停提示
    「本机 AITimeline 没有运行(127.0.0.1:8787),启动后点击重试」;
    重启 API 后点击可恢复。
13. **扩展重载**:在 `chrome://extensions` 里刷新扩展,回到已打开的 x.com
    标签页(不刷新页面)点「保存」,按钮应变「重试」并提示「扩展已更新,
    请刷新页面」,不会永久卡在「保存中…」。

## 人工验收步骤(注入)

x.com 上的 DOM 行为没法无头验证,以下步骤必须真人过一遍:

1. 起本机 API(`npm run dev:api`)和网页应用(`npm run dev`,127.0.0.1:5173)。
   确认知识库里已有卡:`curl -s "http://127.0.0.1:8787/api/inject/cards" | python3 -m json.tool`
   应返回 1-3 张卡(复习到期的优先);返回空数组则先导入几篇文章再验。
2. 重新加载扩展(`chrome://extensions` → 刷新按钮),打开 https://x.com 并登录。
   扩展图标上应出现蓝色 badge,数字=可注入卡数。
3. 滚动信息流几屏,应看到一张「你的知识库 · N 天前存的」卡混在推文之间:
   40px 圆形头像位、标题加粗、摘要、来源标题、蓝色「在知识库中打开」。
   复习到期的卡,meta 行还有灰色小字「 · 该复习了」。
   外观应与前后推文融为一体(分隔线、字体、内边距一致),不重叠不破版;
   标题最多 2 行、摘要最多 4 行,卡高不超过普通推文太多。
4. **三主题**:在 X 的「显示」设置里切换 默认(亮)/ 昏暗 / 熄灯 三种背景,
   每种下注入卡的分隔线、次要文字颜色都应贴当前主题,无突兀色块
   (已插入的卡按插入时的主题着色,切主题后新插入的卡跟新主题)。
5. **只注入主时间线**:进通知页、搜索结果、书签、任意用户主页、推文详情页,
   都不应出现注入卡;回到 /home 恢复注入。
6. **同锚点去重**:热门推文被多人转推、同屏出现两个同链接格子时,注入卡
   只出现一份,不在格子间来回跳动。
7. 频率克制:同屏不应出现两张注入卡(间隔约 8 条推文);整个页面生命周期
   最多 3 张;刷新页面后重新计数。新卡只会出现在当前视口下方(继续往下滚
   才遇到),不会突然插在已经滚过的位置。
8. 滚动存活:把注入卡滚出视口很远(1-2 万像素)再滚回来,卡应还在原来那条
   推文上方、且只有一份(锚点稳定 + 查重)。
9. 点击注入卡:新标签页打开 http://127.0.0.1:5173(网页应用没有单卡路由,
   开首页是预期行为)。
10. 信号回传:注入卡进视口停留几秒后,查
    `curl -s http://127.0.0.1:8787/api/snapshot | python3 -c "import json,sys; d=json.load(sys.stdin); print([ (r['signal']['postId'], r['signal']['dwellTimeMs'], r['signal']['openedThread']) for r in d['interactionSignals'][-5:] ])"`
    应看到该卡的纯曝光记录(dwell 0)、随停留追加的累计 dwell 记录,以及
    点开后 openedThread=true 的记录。
11. **断连重试**:先停掉 API 再打开 x.com——没有注入卡、badge 为空(不造假
    卡),页面无报错;这时启动 API,保持标签页在前台等最多 60 秒(或切走
    再切回来),badge 应出数字;继续往下滚动,注入卡出现在视口下方的推文
    之间(新卡不会插在已经滚过的位置),全程不用刷新页面。badge 是按标签页
    记的,关掉或导航离开该标签页就消失。

## 已知限制

- 太短的推文可能被来源质量检查拒收(判据要求正文有足够词量与实质内容),
  候选会落为 `rejected_source`。长推文/长帖(Article)通过率高。
- 折叠长文与 X Article 的选择器(`tweet-text-show-more-link`、
  `twitterArticle`)按 2026-08-04 真机核验施工:折叠标记是 `<button>显示更多`
  (无 href),点击就地展开正文、不跳转(实测 154→616 字,约 1 秒)。X 改版
  需跟进;万一改成跳转式,插件会在 2.5 秒后退回「跳详情页存全文」的老路。
- **X Article 只能在文章详情页保存**:时间线上的 Article 预览推文没有
  `twitterArticle` 结构,在时间线保存只会存到推文的评论文字,且 URL 幂等
  去重会把这半截永久钉死——要存文章,先点进文章页再点「保存」。预览卡
  的时间线选择器待真机核验后再做拦截。
- 成卡回执靠 background 轮询(2.5 秒一次,90 秒封顶);超时或 service
  worker 被浏览器回收就没有回执,下次保存/刷新会看到「已成卡」。按钮的
  「已保存/已成卡」状态记在页面内存里,刷新页面后回到「保存」(数据无损,
  再点一次会得到「已存过/已成卡」)。
- 只在推文操作栏注入;X 的 DOM 结构(`article[data-testid="tweet"]`、
  `[data-testid="tweetText"]` 等)若改版,选择器需要跟进。
- 注入依赖 X 虚拟列表的格子结构(`div[data-testid="cellInnerDiv"]`)和推文
  `/status/` 永久链接;X 改版需跟进。注入卡的会话计数在页面刷新后归零。
- API 地址写死 `127.0.0.1:8787`,与本机默认一致;不支持配置。
