访问,装载/重载必须真人操作),所以做法是:把仓库里逐字一致的 CSS 与提取逻辑
注入真实时间线,在真实 DOM 与真实前后推文之间验证。API 侧是本机真 API

|---|---|

| 视频 poster | 2 条带视频推文,取到 `amplify_video_thumb` 真实地址,链接补成推文永久链接 |
| 永久链接/作者/正文 | 6 条里 5 条正常;失败那条是广告位(见下) |
| 广告位 | @kusuriya_ads:有正文、有操作栏、有折叠标记,但**没有 time 元素→没有永久链接**,存不了 |
| 注入卡三主题色值 | dark/dim/light 三套计算色值逐条对上 X 调色板 |
| 分类条定位 | 浮在按钮下方 6px,完整落在视口内 |

## 因此改了代码

1. 折叠长推:从「按钮变『点开存全文』导流详情页」改成「点保存时先就地展开再存
   全文」。原方案在中文时间线上会让 2/3 的推文都要跳走一趟。
2. 广告位不再挂按钮(标记 `data-aitl-processed="skip"`,补挂逻辑跳过)。

## 还需要真人做的

- **装载/重载插件**:`chrome://extensions` → 开发者模式 → 加载已解压的扩展程序 →
  选 `apps/extension`。自动化工具进不了 chrome:// 页面。
- **昏暗/亮色两个主题的并排观感**:色值已逐条核对,但「在那个主题下看着像不像
  原生」需要真人切一下 X 的显示设置看一眼(切换会改 X 账号设置,没替你动)。
- **端到端保存链路**(按钮 → background → 本机 API → 成卡回执):需要插件真装上
  才能验;API 侧已由 smoke 覆盖。

## 观察到、没改的

分类条的候选里混着 `data`、`dark-data`、`decoupled-rope`、
`multi-head-latent-attention` 这类内部概念标识,当「分类」给人看偏噪。
机制没问题,是候选来源(`topicStates` 的 topicId)本身就是 slug。
要不要过滤/换成更像人话的显示名,是产品决定,留给用户拍板。
