# 深读文章 v2:让它读起来是文章

## 背景与问题

#115 一期上线后用户实测否决:「这不叫文章,就几个字几个字的」。真实数据诊断(模型稿 Multi-head Latent Attention):全文仅 2557 字 15 段;模型产出 30 段被门禁删一半;6 章中 3 章缺口空壳,其中 2 章因全文去重吞掉重复声明段连缺口说明都没有(0 段)。

根因:①逐章生成是「填表」不是「写作」——prompt 只有正确性约束,无篇幅/叙事要求,无跨章状态;②门禁字面核验只对照**所引 chunk**,把对比语境专名(GQA/MQA)、年份、**主题自身缩写(MLA)**全部误杀,删段后无整章重生成,折损过半直接躺平缺口章;③`dedupeArticleParagraphs` 跨章吞掉相同的模板声明段。

红线不变:grounding 承诺、fact 段引用强制、宁可误杀只适用于**真正无据**的内容;smoke 网络隔离走确定性路径。

## 设计

### 1. 逐章生成改「写作」(`generateModelChapterDraft`)

- prompt 明确:这是给人读的文章正文,不是要点列表;**每章 5-8 段、每段 3-6 句(约 150-350 字)**;段间要承接(上一段结尾引出下一段);章首例子/问题先行,章尾一句接回主线。
- 跨章状态:按大纲顺序逐章生成,把**已写各章的 {title, 一句话要点}** 传入当前章 prompt,要求不得重复、要承接(要点由生成响应自带或从首段截取,确定性)。
- 读者定位(mastered/gap)与结构八条、反 slop 清单保留注入。

### 2. 门禁改「修复阶梯」(`gateDeepReadChapter` / `validateDeepReadKeyFactsLiteral`)

- **字面核验豁免集**:主题名及其别名(过 conceptAliases resolver)+ 本章合同 keyFacts 的值 + 「段落缩写 vs chunk 全称」判定(豁免集 token 归一后含于任一所引 chunk 归一文本的,不算违规;实现按简单可测的规则,不引入模型)。年份/数字仍严格(改数必拦,smoke 既有断言保持)。
- **fact 段阶梯**:核验失败 → 带意见重写一次(保持 fact)→ 仍失败但**引用完整且非悬空**的 → 降级为 `synthesis` 保留并过夸大检测(引用不许丢,#115 M3 的约束保持);**彻底删除只留给引用悬空/引用为空**的段。
- **章级重试**:门禁后若删除 > 1/3,带全部门禁意见**整章重生成一次**再走门禁;仍折损过半才降级缺口章。
- 删段日志、`gate` 报告字段全部保留。

### 3. 缺口章收敛(`createModelOutlineContracts` / 组装)

- 无素材的骨架章**不进正文**;所有缺口(无素材章 + 降级章)聚合为文末一节「本文来源覆盖不到的部分」,逐条列出问题与缺口声明(结构八条的结尾本来就要求「明说没覆盖什么」)。
- 正文只保留有素材支撑的章;正文章数 ≥1 才算生成成功,否则整篇按现有失败路径处理。

### 4. 修去重 bug(`dedupeArticleParagraphs`)

- 跨章去重不得吞掉无引用的模板/声明段(按「有引用的正文段」去重,或按章分组去重);任何缺口条目必须保留其说明文字。

### 5. 验收标准(替换旧标准 5)

1. `npm run typecheck` / `npm run build` / `npm test` 全绿(网络隔离,确定性路径)。
2. smoke-core 增补:字面核验豁免(主题缩写不误杀,构造 chunk 全称/段落缩写 fixture)、fact→synthesis 降级保留引用、章级重试计数、缺口聚合成文末一节、去重不吞声明段;既有「改数必拦」「悬空必拦」「en fallback 存活」断言全部保持。
3. smoke-api 全部保持。
4. 真模型验收(验收人):同主题重生成,量化——**总字数 ≥3500、删段率 <20%、正文空壳章 =0**;验收人通读全文,按「能否顺畅读完、每章是否成文」判定;结构八条与事实回源抽查照旧。

## 明确不做

- 不放宽 grounding:fact 段引用强制、悬空引用必删、改数必拦全部保持。
- 不引入新依赖、不加新模型调用类型(章级重试复用现有生成调用)。
- 不改选料/大纲合同结构/存储 schema(缺口聚合节用现有 chapter 结构表达,status 沿用 "gap")。
- 不动 api 端点、频控、预算;不动 web 入口;阅读视图仅适配缺口聚合节的渲染(若需要)。
- fallback 拼装稿本次不动(预期管理后续单独做)。
