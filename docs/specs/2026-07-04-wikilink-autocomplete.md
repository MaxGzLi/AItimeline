# 双链自动补全

## 背景

#73 引入了 `[[双链]]`,但目前用户必须凭记忆输入准确的概念名或卡片标题,拼错就会变成幽灵链接。需要在输入 `[[` 时给出候选,降低使用门槛。

## 目标

在 web 端的两个输入位置——主发帖框(AskComposer)和帖内回复框(PostView 的回复输入)——当光标处于未闭合的 `[[` 之后时,弹出候选下拉:

- 候选来源:知识库全部概念(优先)+ 卡片标题,按当前已输入的片段过滤(大小写不敏感、子串匹配)。
- 键盘:↑/↓ 移动高亮,Enter 选中,Esc 关闭;鼠标点击也可选中。
- 选中后在光标处补全为 `[[目标]]`(自动补右括号),光标落在 `]]` 之后。
- 无匹配时不显示下拉;手动完整输入 `[[xxx]]` 的旧行为不受影响。

## 不做

- 不改 packages/core(解析/解析优先级维持 #73 现状)。
- 不做移动端(apps/mobile)的补全。
- 不做新概念创建入口(幽灵链接机制已覆盖)。
- 不改根配置、API、数据结构。

## 方案约束

- 两处输入复用同一实现(共享 hook 或组件),不许复制两份逻辑。
- 样式用 xshell.css 既有 token(--x-bg/--x-line/--x-ink/--x-muted/--x-blue),扁平 1px 边框、无阴影渐变,明暗两主题都要工作。
- 下拉在输入框下方浮动,不得引起页面布局跳动。

## 验收清单

- [ ] 发帖框输入 `[[` 出现候选;继续输入即过滤;概念排在卡片标题前
- [ ] ↑/↓/Enter/Esc/点击 全部可用;Enter 选中时不触发表单提交
- [ ] 选中补全为 `[[目标]]`,包括在文本中间编辑的情况(光标位置正确)
- [ ] 回复框行为与发帖框一致(同一实现)
- [ ] 无匹配不弹框;已闭合的 `[[x]]` 之后不弹框;手输 `]]` 旧行为不变
- [ ] 明暗两主题下拉样式正确,截图各一张入 docs/e2e/runs/2026-07-04-wikilink-autocomplete/
- [ ] `npm run typecheck && npm run build && npm test` 全绿;diff 不含 packages/core、apps/api、apps/mobile、根配置
- [ ] UAT:用户可感知功能,合并前截图给用户过目

## 假设与开放问题

- 假设:候选上限 8 条,超出截断(用户可推翻)。
- 假设:匹配片段不高亮(v1 从简,用户可推翻)。
