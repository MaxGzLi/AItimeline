# 半屏刘海面板

状态：**已做完，在 `feat/notch-probe` 上（提交 `b718c17`）。** 探路件按约定不合并，装上真用。

## 背景

用户在刘海探路件上提的：黑窗口太小，中长段文字读着不舒服，想要「一个按钮把整体尺寸拉长，大概半个屏幕，显示更全的文章」。

我先提了另一个方案——刘海上按按钮弹一个我们自己的 Electron 窗口。**用户否掉了**，原话是「我就要在这个刘海窗口上做拓展，我真的觉得这种交互方式值得拓展，后面我们很多通知和其他功能甚至都已走刘海」。

我当时还写过「SuperIsland 是闭源商业 App，fork 不了」。**这句是错的**，用户直接把仓库地址甩了过来：<https://github.com/shobhit99/SuperIsland>，全套 Swift 源码都在。我是在网页搜索额度用完、没核实的情况下下的结论。

所以方案换成：**fork 宿主，把面板尺寸做成插件可以声明的。**

## 目标

刘海展开后的面板从 658×180 放大到约半个屏幕，一张知识卡（概要 + 五段 thread + 相关概念）尽量一页读完。

## 不做

- 不加新的窗口档位（宿主里 `fullExpanded` 出现在 21 个文件里 146 处，加一个 IslandState 分支要动的地方太多）。
- 不做「按一下变大、再按一下变小」的两档切换：`fullExpanded` 本来就是「再展开一次」才到的那一档，已经是那个按钮。
- 不动 `packages/core`。

## 怎么做的

**宿主那边**（补丁在 `apps/notch-extension/host/`，38 行）：manifest 的 `capabilities` 里多认两个字段 `fullExpandedWidth` / `fullExpandedHeight`，`AppState.contentSize(for:)` 读到就用它，按屏幕夹一次上限，没声明的插件走原来的常数。官方那七个扩展一行不用改。

**插件那边**：画布常数改成 836×512，然后重排版面。画布一变，原来给 180 点面板写的排版全都不合适了：

| 原来 | 现在 | 为什么 |
|---|---|---|
| 头版正文最多 3 行 | 按版心剩多少高度算 | 3 行是 180 点面板的真实容量，不是设计上限；照搬到 520 点就是印完三行留一大片黑 |
| 一段 thread 独占一页 | 按「块」拼页，装得下就接着放 | 一段一百来字，在 520 点的面板上只填得掉一成 |
| 概念索引框单开一页 | 最后一段正文先给它留位 | 它只有几行高，自己占一页就是一整片黑（真机量过：一页只填掉一成） |
| 末页剩多少算多少 | 把前一页尾巴上的块挪过来 | 前一页黑边一行都没有、末页黑掉三分之二，看着像没排完 |
| 切页份额 = 总字数 ÷ 页数 | 二分找「还能维持这个页数的最小份额」 | 份额一小，句号处的零头又攒出多一页，越切越碎 |

## 验收（全部已勾）

- [x] 真机量到岛窗 1004×597，插件可用画布 836×512（原来 594×172）
- [x] 真数据十张卡：每张 7 页 → 1~2 页，六张一页读完
- [x] 渲染出来逐页看过：没有黑掉一大半的页
- [x] 新增四条断言：短段落同页、不许塞出版心、索引框不许独占一页、末页不许空一大半；四条都用变异验证过能杀
- [x] 断言一律跟着画布算，不写死点数
- [x] `npm run typecheck` / `npm test` 全绿（321 单测 + 四个 smoke）

## 留给总控的三件事

1. **自己构建的 SuperIsland 没有签名**，等于放弃官方签名版和自动更新。演示机上是不是接受这个，要拍板。
2. **那个仓库没有 LICENSE 文件**，法律上默认「保留所有权利」。自己改自己用没问题，**不能分发**，也不能让用户「先去装我们改过的版本」。要么找作者要授权，要么把这个改动提成 PR 让它进官方版——后者更干净，改动本身是通用的（长文类插件都需要），不带 AITimeline 的任何东西。
3. 用户说「后面很多通知和其他功能都要走刘海」。如果这是真方向，刘海就不再是探路件，得有人决定它在产品里算什么位置——这件事比这次改尺寸大得多。
