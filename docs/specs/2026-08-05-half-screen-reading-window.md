# 半屏阅读窗

状态：**用户已拍板要做，现在做。等总控派人。** 涉及 `apps/desktop` 和 `apps/web`，越出了刘海探路件的范围，所以谁来做由总控 session 定。

## 背景

用户在刘海探路件上提的：黑窗口太小，中长段文字读着不舒服，想要「一个按钮把整体尺寸拉长，大概半个屏幕，显示更全的文章」。

查实过两件事：

1. **SuperIsland 的窗口尺寸插件改不了。** 宿主只给五档：`compact`、`minimalCompact`、`expanded`、`fullExpanded`、`liveActivity`。`fullExpanded` 是最大的一档，扣掉宿主留白后可用 594×172 点，大约五六行正文。manifest 里没有任何尺寸字段（对过官方七个扩展的全部 manifest 字段），JS 接口里也没有改尺寸的调用。
2. **改不了宿主，也 fork 不了。** SuperIsland 是闭源商业 App（`com.workview.SuperIsland` 1.0.10，Developer ID: Shobhit Bhosure T7HT4U4666），应用包里只有二进制，没有源码也没有许可证文件。（源码是否公开在 GitHub 上未核实——查的时候网页搜索额度已用完。）

结论：要更大的阅读面，只能用**我们自己的窗口**，不能指望宿主。

## 目标

刘海上按一个按钮，打开一个我们自己控制的阅读窗：贴屏幕顶部、约半屏高、无边框，视觉上像「刘海拉长了」。窗口里一次读完一张卡的全文和相关概念，不用翻页。

## 不做

- 不改 SuperIsland，不 fork，不给作者提需求。
- 不做多卡浏览：这个窗口一次只读一张卡，翻卡还是回刘海。
- 不动 `packages/core`。

## 怎么做（四块）

| 在哪 | 干什么 | 分量 |
|---|---|---|
| `apps/notch-extension` | 加一个「展开阅读」按钮，`SuperIsland.openURL("aitimeline://card/<id>")` | 十来行 |
| `apps/desktop/src/main.mjs` | `app.setAsDefaultProtocolClient("aitimeline")` + `open-url` 事件；开一个贴顶、半屏高、无边框窗，按 `screen.getPrimaryDisplay().workAreaSize` 定尺寸 | 一百多行（现在只有一个 1280×820 的普通窗，354 行） |
| `apps/web` | 一个「读一张卡」的版面：标题 / 结论 / 概要 / thread 五段 / 相关概念 / 出处 / 复习问题 | 新页面 |
| `apps/api` | 按 id 取整张卡（`/api/inject/cards` 是精简过的，字段不够） | 小 |

## 待定的问题

- 桌面应用没开着的时候，`aitimeline://` 能不能把它拉起来？（Electron 支持，但冷启动几秒，体验要试过才知道。）
- 阅读窗和主窗口（1280×820）是两个窗口，还是主窗口换个尺寸？倾向两个：主窗口是工作台，阅读窗是「读一张卡」，职责不同。
- 这个阅读窗算桌面应用里的一个「房间」（从应用里也走得进去，比如点时间线上的一张卡就用它打开），还是一个独立的小窗口（只能从刘海按按钮弹出来，跟主应用不打照面）？总控之前把桌面应用定成「学习基地」，这个窗口算不算基地的一间房，得有人定。

## 已经落地的相邻改动（不在本提案范围，已合进 `feat/notch-probe`）

把 thread 段落喂进刘海之后，一张卡在刘海里能读的字从 119 涨到 614（中位），一张卡从 1 页变 7 页。**这缓解了「读不到东西」，但没解决「读着累」**——七页翻下来还是不如一屏看完。半屏窗要解决的是后者。
