# Spec: 关系边接地补漏（2026-08-03）

## 背景

「接地是产品承诺」这条铁律，今天只覆盖了**证据句**，没有覆盖**证据句支撑的那个断言**。

2026-08-02 与 GPT Pro 的架构辩论中对方提出四条代码指控，我们用 6 个独立 agent 逐条核实，
并在真实快照 `apps/api/data/aitimeline.json`（只读）上做了量化。核实结论：
**没有编造引文，但在用真引文给没人验证过的关系断言背书。**

量化口径统一为「大小写不敏感、去空白的子串匹配」，已完整复现「60 条两端概念在证据里 / 211 条不在」这一已知事实。

| 事实 | 数值 |
| --- | --- |
| graphEdges 总数 | 271 |
| 两端概念未同时出现在自己 evidence 里 | 211（78%） |
| 两端概念一个都没出现 | 72（27%） |
| extends 边证据里无任何「扩展/基于」线索词 | 42 / 49（86%） |
| requires 边证据里无任何「需要/依赖」线索词 | 58 / 60（97%） |
| 边证据只在 `aitimeline.local` 合成来源里找得到 | 77（28%） |
| 边证据在任何来源里都逐字找不到 | 45（17%，是上限不是确证，翻译改写会误判） |
| 被赋予互相打架 relation 的概念对 | 17 / 203 |
| 至少含 1 条不接地边的卡片 | 93 / 101，其中 85 张标 supported、83 张标 high |
| thread 条目 `grounded: false` 占比 | 510 / 515（99%） |

**注意「线索词缺失 ≠ 关系错」**：「MLA extends MHA」语义上没问题，只是证据句里没写。
但它意味着一件确定的事——现在 92% 的 extends/requires 边，读者和校验器都无法从存下来的证据里核对，
只能选择相信模型。

## 目标

1. 关系边区分「模型断言」与「已核对」，下游只把已核对的当权威。
2. 关系边的两个端点和 `post.concepts` 受同一把接地尺子约束。
3. 切断「模型输出登记成来源，再给模型输出背书」的自证循环。
4. 连接播报卡的信任标签与它「零引文」的事实相符。

## 不做

- 不改 relation 的六种取值本身，不训练/引入关系抽取模型。
- 不做存量数据的批量重生成（存量处置口径见「待拍板」）。
- 不改 `PostDetailView` 现有的关系+证据展示（那是有出处的展示）。
- 全局概念图把数组相邻当关系（`knowledgeGraph.ts:64-70`）本轮不动，见「记账」。

## 工单

### T1 关系边加来源标记，下游按候选消费（最重）

`KnowledgeGraphEdge`（`packages/core/src/types.ts:308-315`）今天连一个「候选/权威」字段都没有，
模型返回的原始 JSON 被 `modelRunner.ts:444-452` 直接 `as KnowledgePost[]` 收下。

- 类型加一个字段区分「模型断言」与「已核对」。
- 下游一律只吃已核对的：`skillTree.ts:126` 的前置知识 DAG、`conceptDigest.ts:101-107` 的角色判定、
  `cardConnections.ts:67-68` 的连接类型判定。
- 验收：库里 92% 无线索词的 extends/requires 边不再产生前置知识关系；旧快照读入时字段缺失有明确默认值
  （建议默认「模型断言」，即存量一律降级）。

### T0 先把接地判定的尺子修准（新增，2026-08-03 体检后插到最前面，T2 依赖它）

**为什么插队**：存量体检测出 `$.concepts[]` 的不通过率是 **164 / 445（37%）**，而挂掉的全是
`Mixture-of-Experts`（11 次）、`Large Language Model`（10 次）、`KV Cache`（8 次）这类**完全正确的技术名词**。
原因不是概念错，是 `normalizedConceptAppearsInText`（`groundingGate.ts:1202`）做的是**连续子串逐字匹配**：

- 不认词形变化：概念写 `Chatbot`、原文是 `Chatbots`；概念写 `ReAct Loop`、原文是 `ReAct loops`（19 条，12%）。
- 死绑单条引文的正文块：概念的依据分布在这张卡引用的**别的**块里就算不通过（145 条，88% 的一部分）。

**在这把尺子修准之前不能做 T2**——给关系边的两个端点套上同一把尺子，卡片产出会直接归零。

**要做的**：
1. 词形容忍：单复数、连字符/空格互换、大小写（大小写现在已经认）。
2. 匹配范围从「某一条 citation 的块」放宽到「这张卡引用的任意一个块」。
3. **不放宽的**：不做语义匹配、不做同义词表、不引模型。只认字面的规则化变体——这是为了让尺子准，不是为了让它松。

**验收**：改动前后在真实快照上跑一遍，报告 `$.concepts[]` 不通过率从 37% 降到多少；
必须有一批「本来就该拒」的反例仍然被拒（新增断言，防止把尺子改松）。

### T2 关系边端点必须过接地检查（最便宜，但要排在 T0 之后）

`sourceConcept` / `targetConcept` 今天只过 `requireString`（`packages/core/src/harness/schema.ts:434/436`），
而 `post.concepts` 是要过接地门禁的（`packages/core/src/harness/groundingGate.ts:149-151`）。
于是一条边可以把来源里从未出现过的概念名直接带进图谱节点（`knowledgeGraph.ts:45`）。

- 端点登记成接地断言，与 `post.concepts` 同一把尺子。
- 验收：新增一条端点不在来源里的边，整张卡被拒（error 级）；smoke 里加这条反例。

### T3 切断合成来源自证循环

271 条边证据里 77 条（28%）只在 `aitimeline.local` 合成来源里找得到——那是跟进卡自己生成的文字被登记成了「来源」。
全库 110 张卡中 30 张的**所有**来源都是这类。这条直接冲撞项目铁律，且不在原始四条指控范围内，是量化时新发现的。

- 禁止把 `aitimeline.local` 生成的内容登记为可引用来源，或在门禁里把合成来源排除出证据池。
- 验收：重跑一轮后「证据只在合成来源里找得到」的边从 77/271 降到 0。
- 存量 30 张卡的处置口径见「待拍板」。

### T4 播报卡的信任标签与零引文相符

`connectionNotes.ts:103/107` 把 `trustState: "supported"` 和 `confidence: "high"` 写死成字面量，
而同一个对象里 `sources: []` / `citations: []` 是空的（`:100-101`）。
全库基线是 supported 97 / emerging 13、high 98 / medium 12——**最没根据的一批卡拿了最高档的标签**。

- 改成 emerging / low，或干脆不带这两个字段。
- 验收：新生成的播报卡不再出现 supported+high；存量 5 张回填。

**界面层的诚实说明**：网页端今天根本不渲染 `trustState`，`formatConfidence` 是死代码，
播报卡在 `apps/web/src/components/PostView.tsx:123-126` 被明确排除在「有出处」徽章之外。
所以这不是今天正在骗用户，是一颗定时炸弹——任何未来的通用消费方（导出、开放接口、第三方）都会按字面值信任它。

### T5 播报卡引用边要用稳定标识，不要复制字符串（按竞态修，不是按「日后编辑」修）

**5 张播报卡里已经坏了 2 张**（`2f443643`、`34a4e599`）：播报卡复制了 `edge.evidence` 字符串，
母卡随后被覆盖，播报冻结了一份作废证据，卡片上再也找不到那句话。

严重性比看上去高：`34a4e599` 的窗口只有 **45 秒**——播报卡是拿母卡的中间版本生成的，
母卡在同一轮导入里就被最终版本替换掉了。所以这是同一轮流水线内的竞态，
光加「引用稳定边 id」不够，还要保证播报只在母卡定稿之后生成（或生成后随母卡一起失效）。
时序证据见 T7 的表格。

### T6 补测试

`cardConnections` 的两条行为目前零覆盖（现有断言只在 `scripts/smoke-core.mjs:1563-1578`，
断的是「不自连、指向真卡、无同伴则为空」）：

- 六种 relation 压成三种 kind 的映射（`cardConnections.ts:144-154`：只有 requires→builds_on、
  contrasts→contrast，其余四种全部塌缩成 leads_to）；
- 「有类型连接无条件顶掉共享概念连接」（`:100-106`，与权重无关，权重 0.01 的有类型边照样顶掉 0.3 的共享概念边）。

### T7 悬案已查清（2026-08-03 结案，不需要单独派活）

原始疑问：`connection-note-34a4e599` 的证据在全库找不到对应的边，只剩一条 `grounded: false` 的 thread 条目
（`moe-meta-pi-003` / `moe-meta-contrast`）作为落脚点，而代码路径只允许抄关系边的证据
（`connectionNotes.ts:130-131` 明确只读 `newPost.graphEdges[].evidence`）。怀疑存在第二条未知路径。

**结论：不存在第二条路径。** 把 5 张播报卡与各自母卡的时间戳对齐后，模式完全干净：

| 播报卡 | 播报生成时刻 | 母卡当前时刻 | 母卡在播报之后被覆盖 | 证据还在母卡边上 |
| --- | --- | --- | --- | --- |
| `connection-note-f9cfba5a` | 07-07 01:38:07 | 07-07 01:36:50 | 否 | 是 |
| `connection-note-2ff4905` | 07-07 01:45:22 | 07-07 01:42:03 | 否 | 是 |
| `connection-note-34a4e599` | 07-08 03:22:40 | 07-08 03:23:25 | **是（+45 秒）** | **否** |
| `connection-note-667f7f31` | 07-08 03:34:01 | 07-08 03:27:55 | 否 | 是 |
| `connection-note-2f443643` | 07-09 03:26:41 | 07-09 09:25:49 | **是（+6 小时）** | **否** |

「证据找不到」和「母卡被覆盖」**完全重合，两两对上**。所以 34a4e599 和 2f443643 是同一个 bug，
就是 T5——播报卡复制证据字符串，母卡随后被覆盖，播报冻结了一份作废证据。

**但这把 T5 的严重性抬高了一档**：34a4e599 的窗口只有 45 秒，说明这不是「偶尔被重写」，
而是**同一轮导入里的竞态**——播报卡是拿母卡的中间版本生成的，母卡在同一分钟内就被最终版本替换掉了。
T5 要按竞态修，不是按「防止日后编辑」修。

那条 `grounded: false` 的 thread 条目是障眼法：母卡 `meta-pi-network-followup-001` 是从
`moe-meta-pi-003` 派生的跟进卡（唯一来源是
`https://aitimeline.local/followups/meta-pi-network-followup-001-...`），
所以同一句话同时出现在母卡的（已消失的）边证据和祖卡的 thread 里，是派生关系的自然结果。

**不过它顺带坐实了 T3**：这条边的证据之所以能过接地门禁，正是因为祖卡那句未接地的推测被登记成了
`aitimeline.local` 合成来源，再拿去给跟进卡的边背书。整条链条从头到尾没碰过一次真实外部来源。
全库 515 条 thread 里 510 条是 `grounded: false`，这个抽水口只有 T3 能关上。

### T10 卡片会被整卡静默覆盖（新增，2026-08-03，比本 spec 其余各条都严重，建议单独立项）

**这是修 T5 时挖出来的真根因，和原假设不同。** 原以为播报卡冻结作废证据是「同一轮导入内的先后顺序」问题，
实际是**两次完全独立调度的任务落在同一个 postId 上，后者把整张卡静默替换**：

- `meta-pi-network-followup-001`：三个独立的 `generate_followup` 任务（07-07 01:39:03 / 07-08 03:17:25 / 07-08 03:23:25）
  各自生成了同一个 postId。播报卡 03:22:40 读到第二版，45 秒后第三个任务整卡覆盖。
- `aux-loss-free-balancing-001`：**两篇不同文章**（swiftscholar.net 07-09 03:23:18、themoonlight.io 07-09 09:25:49）
  各自的 `source_import` 撞在同一个 postId 上，后者 6 小时后整卡覆盖前者。
- 对照：另外 3 张证据完好的播报卡，母卡各自只有一次 harnessRun 命中，没撞车。

**缺陷位置**（已亲自核实）：
- `persistenceStore.ts:1712` `findNearDuplicatePost` 用 `candidate.id !== post.id` **把同 id 候选排除在近重复合并之外**，
  所以同 id 撞车根本不走合并逻辑。
- `persistenceStore.ts:1811-1819` `upsertManyById` 是裸的 `byId.set(item.id, item)`——**整对象替换，无合并、无警告、无审计**。
- `source_import` 和 `generate_followup` 两条链路都走这里。

**存量影响（真实快照实测）**：110 张卡里 **17 张被覆盖过至少一次**；分布为 2 次 10 张、3 次 4 张、4 次 2 张、
**11 次 1 张**（`post-ai-agent-durable-knowledge-001`，且该卡今天已不在库里）。
`post-001` / `post-002` / `post-003` / `post-004` 这批通用编号各被 3-4 次不同日期的 `source_import` 覆盖，
高度怀疑是**无模型兜底路径产出的通用 id**——若属实，则「没配模型时导入第二篇文章会静默销毁第一篇的卡」，
这是比接地问题更硬的数据完整性缺陷。**此推断未验证**（`harnessRuns` 里没有直接的来源 url 字段，
需要顺着 sourceImports/sourceRegistries 关联才能坐实）。

**建议**：单独立项。至少要做到 postId 冲突时不静默替换——合并、拒绝、或改 id 三选一，且留审计记录。
在此之前不要在这个持久化层上再叠新功能。

### T8 存量卡复检的版本兼容禁令（新增，2026-08-03 体检产出）

**这是一条埋着的雷，现在没人踩，但踩上去就是事故。**

体检结论：105 张有引文的卡按今天的门禁重跑，30 张通过、75 张不通过；而 75 张里
**71 张的失败原因能精确追溯到 `#119`（2026-07-10，「Grounding 内核 fail-closed：封死九处放行漏洞」）那次收紧**
——新增「有序词面支持」检查、讨论串标题纳入校验、一批弱证据从警告升级成拒绝。
你的卡有 104 / 105 张生在这次改动之前。

交叉验证：30（今天通过）+ 71（纯因收紧而失败）= **101**，与快照里当年判定 `valid: true` 的数量分毫不差。
另有一个干净对照：唯一一张生在新门禁之后的卡，今天照样通过。
「原文被重新抓取覆盖」（C 类）在这批数据里**零命中**——242 个来源里 241 个只抓过一次，
唯一抓过两次的那个 55 个正文块逐字节相同。

**禁令**：任何「存量卡批量复检 / 清退不合格卡」的功能，**不许直接拿当前门禁跑一遍**，
否则会误杀 71 张内容完全没问题的老卡。要做必须二选一：
按卡片 `createdAt` 对应当时的门禁版本给宽限，或者人工复核，不许自动化下线。
落地时这条要写进代码注释和该功能的 spec，不能只留在这里。

### T9 笔记卡从未经过接地门禁（新增，覆盖面缺口）

3 张笔记卡（`note-6da34968-post`、`note-b75938ca-post`、`note-20e25e82-post`）在 `harnessRuns.outputPostIds` 里
查无记录——笔记走独立的轻量流程，压根不调用 `validateGrounding`。

这不是新 bug，是既有的设计缺口。但它正好落在「用户自己产出内容」这个产品方向的正中间：
**用户自己写的东西没有外部来源，该不该过门禁、怎么过。**
本单不改代码，等产品方向定了一起决策。

## 记账（本轮不动，画出来之前必须先修）

- **概念图关系可视化**：#148 已按本 spec 降级为「只画卡片自身概念的放射图」，不画 relation、不画箭头。
  等 T1 落地后才谈恢复关系可视化。
- **卡片间连接的关系塌缩 + 界面不出示证据**：`PostDetailView.tsx:508` 只渲染 kind，不读已经保留在数据里的
  `connection.relation`，也不渲染 `connection.evidence`。缓解项是同一页另一个区块
  （`PostDetailView.tsx:412-430`）按六种全量标签原样展示了真实关系和证据。
- **全局概念图把数组相邻当关系**：`buildKnowledgeGraph` 只有一个建边函数，`card.concepts` 的相邻对和
  `card.graphEdges` 的带类型边走同一个键、同一个权重累加（`knowledgeGraph.ts:64-70`），
  模型给的关系、权重、证据全丢，方向由数组顺序伪造。今天严重性低，因为这份图的边**没有任何消费者**
  （`wikilinks.ts:213-221` 只读节点，界面画的是另一份图）。哪天把它画出来，顺序巧合会立刻变成无出处的关系断言。

## 待拍板（用户决定，不擅自动）

1. **存量 30 张「所有来源都是合成来源」的卡**：标记降级，还是下架？涉及删用户可见数据，不擅自动。
2. **存量 5 张播报卡**：回填成 emerging/low，还是连卡一起撤掉？
   （它们一共 147 次曝光，点赞 0、收藏 0、展开 0——用户看见了，一次都没认可。）
3. **T1 的默认值**：存量边一律降级为「模型断言」会让技能树的前置知识关系大面积消失，
   短期内技能树会变空。接受，还是先做一轮人工/规则复核？

## 明确不成立 / 被夸大的指控（本次核实撤回的部分）

诚实归诚实，GPT Pro 这几条要撤回或改口：

1. **「任意带非空证据的边都会繁殖成播报卡」——不成立。** 候选要连过五道筛：证据非空
   （`connectionNotes.ts:131`）、两端概念能归一成不同标识（`:140`）、两端都不是图谱里度数前 10% 的枢纽概念
   （`:144`）、命中「最短路 ≥3 跳或不连通且有对应旧卡」或「旧卡已退场 / 该概念下所有卡 ≥14 天无交互」
   其中之一（`:152-190`），最后整批只取最高分的一条（`:68`），且每天上限 2 条（`:59-66`）。
2. **「播报卡被当作正常知识卡展示」——不成立。** 它有独立种类和独立渲染分支（`PostView.tsx:338-348`），
   顶上写着「连接播报 · 派生」，拿不到出处徽章，只有分享和不感兴趣两个操作，停留和曝光埋点被关掉（`:151-155`），
   并被排除在图谱、复习、技能树、深读、概念摘要、掌握晋级、供给计数之外。
3. **「模型产出的边没有任何额外校验」——不准确。** 证据字段过了 error 级接地门禁
   （`groundingGate.ts:139` + `:472`，失败整张卡被丢，`runner.ts:84-85`），另有边数上限和最小权重两条
   警告级检查（`runner.ts:438-454`）。真正无人校验的是三样：关系标签的语义依据、两个端点、
   证据与本条边的对应关系（证据是拿**整张卡的引文汇总文本**做词面重叠，默认档位只要求重叠 1 处、
   共享 2 个词，`groundingGate.ts:381-385`；且以「[超出来源]」开头的证据直接放行，`:256-258`）。
4. **「有类型的连接绕开概念索引、先跑先得」——机制说反了。** 有类型的连接同样要靠概念索引命中才产出
   （`cardConnections.ts:70-72`），两条路都是概念驱动；压制发生在后置过滤（`:100-106`），跟权重无关。
   结论不变，理由要改。
5. **「未验证的关系边在繁殖、绕过了接地承诺」——部分不成立。** 播报卡抄的证据来自母卡的关系边，
   而母卡入库时那句证据已作为 source_fact 过了门禁。问题不在「绕过门禁」，
   在「门禁管的是证据句是否来自来源，从来不管这句证据是否支持那个关系」。

## 最刺眼的五个实例（写给任何要动这块代码的人）

1. **一句营销文案，三种互斥关系，还生了三张卡。**
   `post-grok-advanced-guide-1 / edge-grok-requires-data-analysis`：`Grok --requires--> Data Analysis`（weight 0.9）。
   证据原文是来源站 graphapp.ai 的一句夸赞："Grok stands out as a potent tool for software engineers and data analysts alike."
   同一句话在库里还支撑另外两条边，分别读成 applies 和 extends。它被提拔成用户可见的播报卡
   `connection-note-f9cfba5a`（supported / high，40 次曝光），播报卡又反过来当来源，生出 2 张跟进卡、4 条新边。
   一条没人校验的边，污染半径 = 1 张播报卡 + 2 张跟进卡 + 4 条新边 + 5 个后台任务。
2. **课程广告词被当成三条依赖关系的证据。**
   `post-agent-architecture-patterns` 的 edge-4/5/6 断言 AI Agent requires ReAct Loop / Memory / Tool Interface，
   三条共用同一句招生宣传语「This course takes you inside the architecture of AI agents — the loops, the memory systems,
   the tool interfaces...」。ReAct Loop 这个词在整句证据里根本没出现。
3. **证据来自系统自己标注「未接地」的推测。**
   播报卡 `connection-note-34a4e599`（supported / high，22 次曝光）断言 Meta-Pi Network contrasts Switch Transformer。
   全库没有任何一条边是那句话或那个概念对；那句话唯一的落脚点是一条 `grounded: false` 的 thread。
4. **死去猫咪的告别信，被当成「微调应用于情感 AI」的证据。**
   `grok-4-1-emotional-response / edge2`：Fine-tuning applies Emotional AI（weight 0.8）。
   证据是一段网友描述 Grok 帮自己给死去的猫写告别信的轶事，整句里既没有 Fine-tuning 也没有 Emotional AI。
   同样被提拔成了播报卡（supported / high，34 次曝光）。
5. **一句话没提 AI Agent，却生成三条 evaluates AI Agent 的边。**
   `post-1` 的 edge-1/2/3 都是 X --evaluates--> AI Agent（weight 均 0.9），共用证据
   "LoCoMo, LongMemEval, and BEAM benchmarks are now the standard for comparing memory architectures."
   原句评价的对象是 memory architectures，从头到尾没出现 AI Agent。

## 核查方法

6 个独立 agent 并行：4 个对抗性复核 GPT Pro 的四条代码指控（要求默认往「指控不成立」判），
1 个在真实快照上做污染半径量化，1 个综合。快照只读，未做任何修改。
