# 自己的刘海宿主

状态：**用户已拍板做这条路**（2026-08-05）。何时开工、谁做，等总控排。

## 背景

刘海面板放大到半屏之后（见 `2026-08-05-half-screen-reading-window.md`），用户的判断是这个交互值得往下做：「后面我们很多通知和其他功能甚至都已走刘海」。

继续用别人的宿主有两个卡点：

1. **画不了图。** SuperIsland 给插件的是一套固定组件（文字、图标、进度条、按钮），`image` 只接受图片网址。脑图、架构图、知识图谱——用户反复说要的那些——在它上面做不出来。
2. **不能分发。** 那个仓库没有 LICENSE 文件，法律上默认保留所有权利。自己改自己用没问题，但 AITimeline 的用户不能被要求「先去装我们改过的 SuperIsland」。

用户的决定：自己写一个，**代码结构可以照它的来**，动画和交互手感照抄（那部分他认为做得好），顺便把慢的地方修掉，并且要留出和我们自己 App 打通的口子。

## 目标

一个我们自己的 macOS 刘海应用，做到：

- 手感和现在一样：悬停出小条，点一下出半屏面板，同一套弹簧动画。
- **面板内容能画图。** 知识图谱、配图、任何网页能画的东西。
- 内容更新是**推**过来的，不是等定时器。现在最长要等 86 秒才重画一次。
- 和 AITimeline 桌面应用双向连通：刘海里点一张卡能在应用里打开；应用里发生的事（刚存的东西变成卡了、复习到期了）能推到刘海。
- 我们自己发版、自己签名，用户装一个 App 就够。

## 不做（v1）

- 不做第三方插件系统。SuperIsland 的 `ExtensionHost` 有 6170 行，是为「别人写插件」准备的；我们自己就是唯一的内容源。
- 不做它那些自带模块（音乐、天气、计时器、提词器、剪贴板架等，37 个文件 12195 行）。
- 不做设置界面的全套（它有 2637 行）。v1 只要几个开关：开机启动、悬停延迟、关掉。
- 不做没有刘海的 Mac 上的完整体验。v1 认准有刘海的机器，其它机器退化成一个菜单栏图标，不假装。

## 怎么做

### 结构（照它的来，不逐字抄）

它整个仓库 30907 行，但**壳只有一千来行**，其余都是模块和插件系统：

| 它的文件 | 行数 | 我们要什么 |
|---|---|---|
| `Window/ScreenDetector.swift` | 120 | 刘海在哪、多大、哪块屏有刘海 —— 这部分是纯几何，照做 |
| `Window/IslandWindow.swift` | 54 | 盖在菜单栏之上的无边框窗口 |
| `Window/IslandWindowController.swift` | 457 | 窗口定位、跟随屏幕变化、状态切换时改尺寸 |
| `Views/IslandContainerView.swift` | 452 | 刘海形状、外扩圆角、悬停/点击手势 |
| `App/AppState.swift` 的状态机部分 | ~600 / 2039 | 三档状态、自动收起、悬停延迟 |

我们要写的量级：**两千行上下**。

### 动画参数（照抄，这是用户点名要留的）

- 展开/收起：`spring(response: 0.48, dampingFraction: 0.8)`
- 面板内换内容：`easeInOut(duration: 0.22)`
- 系统开了「减弱动态效果」时：`easeOut(duration: 0.12)`
- 悬停展开延迟：默认 0.3 秒，可调 0～1.5 秒

### 画布：小条用原生，面板用网页

- **静默条和小条**用原生 SwiftUI 画。它们一直挂在屏幕上，必须便宜。
- **半屏面板**用 WKWebView，内容复用 `apps/web` 那套 React。图能画了，样式和网页那边天然一致。
- 这一条是整个方案里最需要先验证的：透明背景、圆角裁切、鼠标事件、内存占用，四样都得在原型上量过才算数。

### 和我们 App 的口子

三条通路，都要有：

1. **本机接口**：刘海直接读 `127.0.0.1:8787`（现在的插件就是这么干的，通路是通的）。
2. **推送**：接口那边开一个长连接，有新卡、复习到期、剪藏转化完成就推过来。取代现在最长 86 秒的定时器。
3. **互相唤起**：刘海里点「在应用里打开」走 `aitimeline://card/<id>`；桌面应用要让刘海弹个东西出来，走本机接口下一条通知。

### 顺便修掉的

- **内容延迟**：现在插件的重画定时器最长 86 秒才跑一次，卡片状态是过期的。改成推。
- **展开时的窗口抖动**：它的做法是展开前先把窗口放大到最大尺寸，收起后 0.55 秒再缩回去，中间还要重建鼠标跟踪区（`IslandWindowController.swift:200-290`）。悬停发飘、时不时自己跳出来，根子在这。我们的做法：窗口尺寸不动，只动里面那层的裁切区域。
- 空闲开销现在是 0.1~0.9% CPU、35MB 内存 —— 这个不差，作为不许退步的底线记下来。

## 验收清单

- [ ] 有刘海的 Mac 上：静默条贴合刘海，悬停 0.3 秒出小条，点一下出半屏面板，收起动画和现在一样（并排录屏对比）
- [ ] 半屏面板里能画出一张知识图谱（这是走这条路的理由，必须有实证）
- [ ] 新卡从本机接口产生到刘海上可见 < 3 秒（现在最长 86 秒）
- [ ] 空闲 CPU ≤ 1%、内存 ≤ 60MB（当前 0.1~0.9% / 35MB，WebView 会涨，涨到多少要量）
- [ ] 从刘海点进桌面应用能打开同一张卡；桌面应用能让刘海弹出一条通知
- [ ] 手不小心蹭到屏幕顶部时，不会掉下来半个屏幕
- [ ] 拔插外接屏、合盖再开、切换全屏应用之后，刘海还在该在的位置
- [ ] 自己签名、能直接双击运行，不需要在系统设置里放行

## 假设与开放问题（用户可推翻）

1. **半屏面板用 WebView。** 好处是能画图、能复用网页代码；风险是四样（透明、圆角、鼠标、内存）没验证过。**建议先花半天做个原型量一量，再决定要不要走。** 如果 WebView 不行，退回原生渲染，但「能画图」这个目标就得另想办法。
2. **v1 不做第三方插件系统。** 如果以后想让别人给刘海写东西，那是另一个决定。
3. **和作者的关系。** 用户已授权按结构自己写。补一句成本很低的保险：给作者开个 issue 或发封邮件说明我们参考了他的实现，顺便把「面板尺寸可声明」那个改动提成 PR —— 那个改动是通用的，不带 AITimeline 任何东西。做不做由总控定。
4. **开工时机。** 这是一周量级的活。改过的 SuperIsland 今天就能用，演示够用。**建议不要挤掉冲刺里的其它线**，等冲刺之后开工；如果总控认为刘海是演示主线，那就另说。
