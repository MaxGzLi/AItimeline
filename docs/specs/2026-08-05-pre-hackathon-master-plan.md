## 三、界面结构：学习基地，不是编码台

抄的是 Codex 的视觉语言，不抄它的信息结构。对应关系如下：

- **左栏两级**（Codex 是「项目 → 会话」）→ 我们是「学习主题/目标 → 该主题下的对话与任务」。
  顶部固定入口：今天（哄着学的信息流）、复习（带到期数）、收集箱（剪藏/导入待消化）；
  底部：图书馆（全部卡片/概念/图谱）、设置。旧的八个视图归进这些入口，不再平铺。
- **中栏对话流**（默认屏）→ 打开就有 agent 先说话：今天排给你的卡、连接播报、
  到期复习提醒，都是它发的「帖子」，像社交流一样往下走——绝不出现空聊天框（红线）。
  用户在底部输入：提问（带出处答）、派活（导入/深挖）、说偏好。
  消息不对称：你的话是右对齐浅色块，agent 的内容是无容器散文 + 卡片。
- **右栏上下文卡**（浮起）→ 当前主题的概念小图、知识边界三区、复习队列、正被引用的来源。
  现有 ContextRail 改装，不新写。

## 四、agent 运行时第一步（赛前唯一架构动作）

目标：对话不再是「预设四个端点」，而是一个真的循环——模型看情况、选工具、看结果、再决定。

- **协议**：纯文本 JSON 协议跑在现有「补全」接口上（模型每轮输出
  `{"tool": ..., "args": ...}` 或 `{"say": ...}`，服务端校验后执行，最多 N 步）。
  这样 OpenAI 兼容客户端和命令式客户端都能跑，不用动模型层接口。
- **工具箱**（全部是现有能力的薄封装）：导入来源、搜索发现、有据问答、
  生成跟进卡、排复习、读/写用户记忆。
- **护栏不变**：凡是说给用户的知识内容必须过接地门禁带出处；出网搜索先征求同意；
  无模型时确定性兜底（列出可做动作让用户点选），冒烟测试必须网络自由跑通。
- 演示脚本三个动作跑通即算达标：问答带出处、派活导入成卡、到期复习完成。
