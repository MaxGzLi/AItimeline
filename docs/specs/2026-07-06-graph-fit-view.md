# 图谱初始视角 fit-to-view(打开即看全)

## 背景

打开「图谱」页,点云挤在画布上半部、右侧节点标签被裁、下半部大片空白;用户必须手动滚轮缩小才能看全。2026-07-06 排查根因(全部现状事实):

- 画布是 Canvas 2D,力导向布局在前端 `apps/web/src/components/LinkedGraphCanvas.tsx:144-213`,容器 `.x-graphcanvas` 是 `width:100%; height:70vh; overflow:hidden`(`apps/web/src/xshell.css:1482-1490`),典型形状「窄而高」。
- 相机逻辑只有一条:首次拿到尺寸时把**世界原点 (0,0)** 钉到视口中心(`LinkedGraphCanvas.tsx:530-534`),`scale` 硬编码初值 1(`:60`),**没有任何按节点包围盒计算缩放/平移的 fit-to-view**。
- 节点初始坐标由 hash 伪随机撒在原点周围(`:126-140`),向心力弱(`CENTER_PULL=0.012`)、alpha 衰减快,点云质心收敛后普遍偏离原点 → 整团偏移;斥力大(`REPULSION=2600`)节点多时点云宽度超过中间列宽。
- concept/ghost 标签总是画在节点右侧 `point.x + radius + 4`(`:340-345`),最右侧节点的标签被 `overflow:hidden` 裁掉。
- 已有滚轮缩放(`:507-520`,MIN 0.35 / MAX 3)和拖拽平移(`:429-505`),交互本身没问题,缺的只是初始视角。

## 方案

给 `LinkedGraphCanvas` 加 **fit-to-view**:

1. **包围盒计算**:遍历全部节点求 min/max(x,y),右侧再加标签宽度余量(可用 `ctx.measureText` 或固定估宽,比如每字符 ~7px × label 长度,取简单可靠的做法),四周留 padding(约 24-32px)。
2. **fit 时机**:
   - 首帧布局出来后 fit 一次(可先跑几步模拟再 fit,避免用初始随机撒点定视角);
   - 力导向 `settle()` 收敛结束(`:398-407`)后再 fit 一次,把最终形态收进视口;
   - 简化替代方案也接受:在 alpha 收敛前的每帧持续软 fit(插值过渡),收敛后停。二选一,以实现简单、视觉不跳变为准。
3. **fit 计算**:`scale = clamp(min(viewW/bboxW, viewH/bboxH), MIN_SCALE, 1)`(不为了小图放大超过 1),`tx/ty` 把包围盒中心映射到视口中心,替代现在 `:530-534` 的「原点居中」。
4. **用户接管后停止自动 fit**:一旦用户滚轮或平移过(已有交互回调里立 flag),不再自动调整视角。节点拖拽不算接管(拖个别节点不该重置视角)——按实现难度取舍,至少滚轮/平移后必须停。
5. **右栏局部图谱**同用此组件(高度 320px 覆写,`xshell.css:1533-1538`),fit 逻辑必须对它同样生效且不退化——它节点少,注意 clamp 到 scale≤1 别放大到怪异。
6. **窗口 resize**:`ResizeObserver` 回调(`:522-536`)里,若用户尚未接管视角,按新尺寸重新 fit;已接管则保持现状行为。

## 明确不做

- 不改力导向常量(REPULSION/SPRING 等)和布局算法本身;fit 是相机层的事。
- 不加缩放按钮、小地图、「重置视角」等新 UI 控件。
- 不动 `packages/core`(拓扑生成与坐标无关)。
- 不改 GraphView 的 tab 结构和边界列表。

## 验证标准

- `npm run typecheck`、`npm run build` 全绿;`npm test` 不受影响(纯前端改动)。
