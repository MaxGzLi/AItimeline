# Spec: 信息流新鲜感——曝光降权 + 会话轮换（2026-08-02）

## 背景

推荐页每次打开都是同一批卡同一顺序，首屏永远是同一张卡。根因：`rankPersonalizedTimeline` 是纯确定性打分排序，输入不变输出就不变；且只有「读过」的卡有 `seenReadPenalty`（每次 ×12、封顶 36），**只被曝光但没点开的卡完全不降权**，高分卡永久霸屏。用户期望像 X 一样每次打开都有新鲜感。

用户已拍板：走「曝光降权 + 轮换」，不做强制新内容置顶（没曝光过的卡疲劳为零，自然会浮上来）。

## 目标（写行为，不写实现）

1. **曝光疲劳**：一张卡被刷到过（有 impression 信号）但没有互动（无点赞/收藏/深读），再次打开时排位逐步下降；降权随累计曝光递增、有封顶，卡不会因此彻底消失。带互动的那次曝光不计入疲劳；已读的卡此后若仍被反复曝光且无互动，疲劳照常累计，与已读降权叠加（2026-08-02 验收裁决：按「方案」段的按条计口径——卡级豁免会导致互动过一次就永久免疫，违背新鲜感目标）。
2. **会话轮换**：相近分数的卡在不同次打开（页面加载）时呈现不同顺序；同一次会话内的翻页/轮询刷新顺序稳定，列表不跳动。
3. **首屏可感知**：数据量足够时（候选 ≥ 5），连续两次打开页面，首屏第一张卡不同。这是本单的核心验收。
4. **无 seed 完全兼容**：不带会话 seed 的请求行为与现状一致（纯确定性），smoke 与既有测试不破。

## 不做

- 不改供给侧：不强制最新导入的卡置顶，不动 curation/refill 逻辑。
- 不动复习到期卡的插入逻辑（`dueReviewPostIds` 优先级照旧）。
- 不动主题块编排的结构（`arrangeTimelineBlocks` 的块规则不变，只消费新的 rank 顺序）。
- 不新增持久化结构：曝光计数从现有 `interactionSignals` 聚合得出。

## 验收清单

- [ ] 单测：曝光 N 天未互动的卡，分数低于同等条件未曝光卡；惩罚随 N 递增且封顶。
- [ ] 单测：同 seed 两次排序输出完全一致；不同 seed 在相近分数段产生不同顺序；不传 seed 时输出与改动前完全一致。
- [ ] 单测：轮换只发生在分差受限的相邻段内，低分卡不会被抖进首屏（断言能杀死「全局随机洗牌」这种错误实现）。
- [ ] smoke-api：带两个不同 seed 请求时间线，首位 postId 不同（候选足够时）；不带 seed 请求两次，输出一致。
- [ ] UI 验收：刷新页面两次，各截一张首屏图，第一张卡不同。
- [ ] 现有约定不破坏：impression 信号恒 dwell 0、dwell 聚合按 postId 取 max（#114）；复习到期卡仍按期出现。

## 假设与开放问题（用户可推翻）

- seed 由网页每次页面加载生成一次，同一页面存活期内所有时间线请求复用同一 seed；刷新即换。
- 「互动」的判定沿用现有 qualified 信号口径（点赞/收藏/深读/足够 dwell），细节在设计门禁定。
- 轮换的分差窗口（ε）与疲劳梯度/封顶数值在设计门禁定，验收只看行为。

## 设计门禁

命中「改核心公共包」（`packages/core/src/ranking/`）：实现前需一页方案草图（ranker 新输入签名、曝光计数聚合口径、抖动算法与窗口、API 透传方式），主会话批。

## 方案（设计门禁 2026-08-02 主会话批准）

- `PersonalizedTimelineRankingInput` 新增可选 `sessionSeed?: string`；不传时输出与现状完全一致。
- **曝光疲劳**：ranker 内部从合并后的信号推导——每个 postId 统计「有 impression 且无互动」的合并信号条数（互动 = liked / saved / openedThread / askedQuestion / reviewed，或 dwell 达到现有已读阈值）；惩罚 = min(条数 × 8, 24)，复习到期卡豁免。数值与现有 seenReadPenalty（12/36）同量级，实现时可按测试微调，但「递增 + 封顶 + 复习豁免」三性质不变。
- **会话轮换**：排序完成后做一次窗口内旋转——从头扫 ranked 列表，窗口 = 与窗口首分差 ≤ 10 的连续段；窗口内按 hash(seed + postId) 重排（FNV-1a 或同类确定性哈希，禁用 Math.random）。导出纯函数供单测。
- **API**：`GET /api/timeline?seed=<≤64 位 [A-Za-z0-9_-]>`，校验后透传 ranker；非法 seed 忽略（等同不传）。
- **Web**：lib/api.ts 模块级生成一次 seed（页面加载时），时间线请求统一附带；刷新页面即换。不动 App.tsx（避免与并行的 visuals 单冲突）。
- **取舍**：轮换放在 rank 层而不是块编排层——块分数由成员分数聚合，曝光惩罚会自然带动块顺序变化；若 UI 验收发现首卡变化不明显，再考虑块编排层补强（本单不做）。
