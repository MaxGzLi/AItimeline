# 推荐时间线内容生命周期(看过的卡怎么退场、新卡怎么到达)

## 背景

用户指出推荐流缺一套内容生命周期规则:出现过的内容一直保存,但没有「什么时候退场、什么时候标记不感兴趣」的机制;新生产的内容也没有到达提示(对标 X 顶部的「显示 35 帖子」按钮;因为我们的内容是生产出来的,还可以显示「新内容生产中 x/N」)。

现状的三个事实(2026-07-06 排查):

- 排序器(`packages/core/src/ranking/ranker.ts`)完全没有「看过」的概念:`InteractionSignal.impression` 字段存在但从未被排序使用。一张高分卡永远排最前,新卡被埋,信息流显得静止、重复。
- ✕「不感兴趣」已存在:记一条 `skippedQuickly` 信号(同主题降权 + 疲劳度),但卡片只是前端本地隐藏,刷新就回来——没有持久的「这张卡别再推」。
- 前端每 60 秒静默整体替换时间线(PR #92):能同步服务端删除,但严格说会在阅读时原地重排,应改为「冻结 + 缓冲 + 顶部提示」。

「读过」的判定不用新埋点:PostView 已基于视口停留上报 dwell 信号;需要补的是轻量「曝光」上报(卡片进入视口即记 impression),用于「曝光多次却从不阅读」的退场判断。

## 卡片在推荐流里的生命周期

```
新卡(未读)→ 在场(读过,逐次衰减)→ 退场(不再进推荐)→ 复习回流(间隔复习到期)
```

1. **已读衰减**:排序时按该卡的已读次数扣分(每次读过 -12,封顶 -36,数字可调)。读过的卡逐渐下沉,给新卡腾位置;信息流自然轮换而不是静止。
2. **退场(回收)**:满足任一条件即不再进推荐流(卡仍保存——「最新」标签、知识图谱、搜索、已收藏都还在):
   - 用户点 ✕ 不感兴趣 → **该卡立即永久退场**(持久化,替代现在的本地隐藏),并保留现有的同主题降权信号;
   - 曝光 ≥ N 次且零互动(没读、没赞、没存、没追问)→ 自动退场;
   - 读过且连续 D 天无新互动 → 自动退场。
   (N、D 见「待拍板」。)
3. **回流**:唯一回流通道是间隔复习(review 模块已有)。复习到期的卡带「复习」意图重新出现,不与新卡按同一套分数竞争。回流位置见「待拍板」。

## 新内容到达(X 式)

1. **信息流冻结 + 缓冲**:60 秒同步改为 diff——服务端已删除的卡立即移除(保留 #92 的初衷),**新增的卡进缓冲区**,当前列表顺序保持稳定,不在用户阅读时重排。
2. **顶部 pill「显示 N 张新卡」**:缓冲区有新卡时,在发帖框下方(X 同款位置)弹出;点击 → 新卡按排序插入顶部并滚动回顶。
3. **生产进度「新内容生产中 x/N」**:后台有进行中/排队的生产任务(导入、跟进、发现)时,同一位置显示进度;x = 本批已产出并释放的卡数,N = 本批计划数(从任务队列 + release plan 可得)。批次完成后切换为「显示 N 张新卡」。

## 分层落点

- **core / ranker**(Codex 任务书):已读衰减(输入加每卡已读次数)、退场过滤(dismissed + 自动退场规则)、复习回流意图;smoke-core 补覆盖。
- **core / 存储**:快照新增每用户 dismissed 卡 id 集合;已读/曝光次数直接从既有 `interactionSignals` 推导,不加新表。
- **apps/api**:`/api/timeline` 应用退场过滤;✕ 走新的持久化 dismissal 接口(同时仍记 `skippedQuickly` 信号)。
- **apps/web**(主会话亲自做):曝光上报(进入视口 ≥1s,批量发送)、同步改缓冲 diff、顶部 pill、生产进度条、✕ 调持久化接口。

## 明确不做

- 语义级重复合并 / 每种子卡跟进冷却期(单独决策,不混入本期)。
- 推荐分数的时效加成大改:pill 置顶插入已解决「新卡可见性」,只保留现有的小幅 freshness 加成。
- headless/e2e 页面的曝光信号豁免(已知污染源,单独处理)。

## 已拍板(2026-07-06)

1. 自动退场门槛:**曝光 5 次零互动退场;读过后 30 天无新互动退场**(宽松档,适合当前内容产量)。
2. ✕ 的作用范围:**一键双效**——该卡永久退场 + 同主题降权(现有 `skippedQuickly` 信号保留),不弹菜单。被 ✕ 的卡也不再进复习回流。
3. 复习回流:**到期复习卡带「复习」标识混进推荐流**,卡上多一个「已复习」确认按钮;确认后该卡从流里消失,按间隔递进(1→3→7→14→30 天)排下一次到期。复习状态需服务端持久化(现状是纯前端按信号临时算,无完成记录)。

补充约定:纯曝光信号(`impression: true`、`dwellTimeMs: 0`、无任何互动标志)对主题兴趣/理解度必须是中性的,只用于生命周期统计——否则轻量曝光上报会把主题分拉低。
