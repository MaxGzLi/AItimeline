# 深读文章:把一个主题的知识穿成有据长文

## 背景与目标

用户体感「单一帖子的学习深度不够,没有对一个知识的完整理解」。本功能把一个主题下的闭包卡片 + 原文片段穿成一篇结构化深读文章。对比坐标是市面上用 AI 生成文章的博主——他们的不负责和故意夸大是反面教材。卖点:**事实细节正确、读完真有收获、个性化**(我们知道读者已掌握什么,通用博主做不到)。

方法架构依据 2026-07 调研(STORM/WebWeaver/VeriScore 一脉 + 金字塔原理/Diátaxis/认知负荷 + Anthropic doc-coauthoring/反 slop 工程实践),核心教训:**57% 的引用是事后合理化,门禁救不了生成顺序,必须生成时就「先素材后句子」**;引用蕴含校验抓不住「在两条真素材之间捏造联系」,要靠 synthesis 显式标注 + 夸大检测。

## 设计(六阶段管线,core 新模块 `packages/core/src/deepread/`,api 接线)

### 0. 选料(确定性,零模型)

- 输入:主题概念(从学习目标或技能树入口触发)。
- 取料:概念闭包命中卡(概念归一走 alias resolver 口径,照 #111/#114 先例)+ 卡引用指向的 `sourceRegistries` chunks 原文 + 用户该主题下的提问/笔记。
- **准入分截断**:来源可信度(复用 `sourceQualityVerdicts` 降分信号)+ grounding 通过情况 + 与闭包重合度;不够分进**弃料清单**(记录理由,随文章存档),不硬凑。
- **冲突预检**:同一事实字段(数字/日期/版本号/专名)在多卡间不一致 → 标「冲突对」,交给大纲决定并陈或划缺口。
- **覆盖率下限**:一章 ≥2 独立来源;单一来源撑的章节标 `singleSource: true`。

### 1. 大纲(强模型,两步;「大纲即素材分配表」)

- 第一步:凭模型参数知识出草稿骨架(泛而有序)。
- 第二步:用选料 refine——**每个章节节点挂具体素材指针(卡 ID + chunk ID),无素材可挂的节点删掉或转缺口章**。
- 每章产出一份**章节合同**:本章回答的问题(一句话)、引用池(素材指针清单)、**关键事实清单**(数字/专名/日期从引用池预抽取,确定性代码)、缺口声明、冲突处理指令(若有冲突对)、`singleSource` 标记。
- **读者定位**:从技能树取该用户 mastered / gap 概念清单注入合同——已掌握的概念少铺垫,gap 概念多铺垫(先行组织者,机械取自数据,不靠模型臆测)。
- **多角度只在此处**:大纲产出后一次**对抗审纲**(独立调用:章节划分偏科吗?冲突对处理了吗?缺口标了吗?),按意见修一轮。不做多份大纲评选,不做多 agent 写作。

### 2. 逐章生成(强模型)

- 每章生成器**只拿到本章引用池的素材原文(带 ID)**,拿不到全库;跨章只共享结构状态(已写章标题 + 每章一句话要点),不共享全文。
- 输出结构化段落 `{ text, citations: [{ sourceId, chunkId }], kind: "fact" | "synthesis" }`:fact 段必须带引用;跨素材推断/过渡/观点必须标 `synthesis`(语言上也要可区分,如「把这两件事放在一起看……」)。
- 生成 prompt 固定注入两份规则(落盘为 core 内常量文件,非散落 prompt):
  - **结构八条**:开头=用已掌握概念搭桥+造问题(SCQA);具体先于抽象、例子先于定义;每段最多一个新概念、按依赖排序、章尾接回主线;是什么必配为什么+取舍;事实断言挂来源、观点与事实可区分;**来源里的限定语不许丢**(相关性不写成因果、相对数字配绝对数字);类比短且标边界;结尾=可复述的收获+明说没覆盖什么。
  - **反 slop 清单**(Wikipedia《Signs of AI writing》中文化):禁语表(「值得注意的是」等)、结构反模式(否定对仗「不是 X 而是 Y」、三连排比、空洞总结段、加粗小标题列表腔)。

### 3. 逐段门禁(每段独立,宁可误杀)

- **存在性校验**(纯代码):citation 的 sourceId/chunkId 必须在注册表中,无悬空引用。
- **关键事实字面核验**(纯代码):章节合同的关键事实清单逐一与段落文本比对,数字/专名/日期不一致即 fail。
- **支撑性校验**(模型):仅对 `kind: "fact"` 段逐句判断是否被所引 chunk 蕴含;synthesis 段不做蕴含硬校验(避免把分析逼成复读机),但过**夸大检测**:有无超出来源的强断言、营销腔、因果升格。
- **机械反 slop 检查**(纯代码):禁语命中数、段首句删除测试(删掉段首句段意不损则该句为废话)。
- fail → 带门禁意见重写一次 → 仍 fail 静默删段并记日志(存档在文章记录里);**章折损过半 → 降级为缺口章**(明说「本文来源不足以支撑」)。

### 4. 组装(默认模型,失败走确定性)

- 引言(先行组织者 + 一句话答案)、结论(「读完你能回答什么」+ 边界)、全文去重、来源清单 + 库版本戳(生成时的 snapshot updatedAt)。
- 计算**知识密度**观察指标(去重原子要点数/长度,首版记录不做硬门禁)。

### 5. 新读者测试(终门,记档不硬拦)

- 一次**干净上下文**的独立模型调用:只喂成稿,回答每章合同里的「本章问题」+ 找矛盾/歧义;结果作为质量报告随文章存档,供阅读视图展示与后续迭代,不拦发布(首版)。

### 6. 入库与阅读(api + web)

- snapshot 新增 `deepReadArticles: DeepReadArticleRecord[]`(含章节/段落/引用/弃料清单/删段日志/质量报告/版本戳)。
- api:`POST /api/deepread`(入队后台 job,新 kind `deep_read_article`,用户显式触发,不占每日自动生产预算,单独频控每天 ≤1 篇)+ `GET /api/deepread` / `GET /api/deepread/:id`。
- web:技能树/学习目标详情加「生成深读文章」入口;阅读视图 X 风格贴左、每章末尾「本章事实来源」、缺口章和 synthesis 段有克制的视觉区分、文末来源清单。生成中/失败状态可见。

### 模型与预算

- 模型分层:`AITIMELINE_MODEL_DEEPREAD_NAME/_BASE_URL/_API_KEY/_MAX_TOKENS`,未配回落默认 `AITIMELINE_MODEL_*`(用 `createOpenAICompatibleModelClientFromEnv` 的 overrides);核验与生成同档。
- 降级链:深读模型 → 默认模型 → **确定性拼装稿**(按概念树成章,每章罗列卡片要点+引用,标明 fallback 形态)——smoke 网络隔离全走这条。
- 单篇预算:env 可配 token 上限(默认 100k,接受 50k-150k 区间),超限截断章节数并在文中声明。

## 明确不做

- 不做多 agent 写作/多份大纲评选(调研结论:成本 3-5 倍,失真源增加,收益在文采不在事实);
- 不做开放网络检索补料(素材闭集,不够就明说缺口);
- 不做文章编辑器、导出/分享、自动重生成(库更新后手动重新生成);
- 不改现有单卡管线、grounding 门禁、时间线/编排逻辑;
- 不引入新 npm 依赖;不在浏览器调模型。

## 验证标准

1. `npm run typecheck` / `npm run build` / `npm test` 全绿(网络隔离,全走确定性 fallback)。
2. smoke-core:选料准入分与弃料清单、冲突预检、大纲合同结构与无素材节点处理(fallback 路径)、存在性校验拦悬空引用、关键事实字面核验拦改数、章折损降级、确定性(同输入同输出)。
3. smoke-api:POST 入队与频控、无模型 fallback 文章完整入库、GET 返回、文中所有 citation 可在 registry 解析、弃料清单与删段日志字段存在。
4. UI 截图(验收人):阅读视图(浅/深色)、缺口章与 synthesis 区分、来源清单、生成中状态。
5. 真实验收(验收人):配模型生成一篇真实主题文章,人工过结构八条 + 反 slop 清单 + 抽查 3 处事实回源。
